# 명세 검토 체크리스트: 환불 기능 완료

**갱신일**: 2026-10-26 · **기준**: [spec.md](../spec.md), 정책 v0.4

## 문서 내용·추적

- [x] 환불 확정과 PG/별도 환불금 지급을 구분하고 이용 종료·금액·동의를 설명한다.
- [x] 환불금 지급 실패에도 이용권·좌석을 복구하지 않는 결정을 반영했다.
- [x] 고객·매장 판정과 권한, 미지급 목록, 운영 재처리, 환불금 중복 지급 방지, 실제액 원장·알림을 정의했다.
- [x] 10개 스토리·92개 시나리오·60개 요구사항·25개 성공 기준을 문서 간 대조 대상으로 정했다.
- [x] 모든 시나리오의 다이어그램과 HTTP 검증 항목을 별도 문서에 둔다.
- [x] 개별 PG 확인의 권한·결과·전역 복구와의 분리·중복/최근 조회·확정 실패 처리를 명세·API·검증 항목에 연결했다.
- [x] 개별 확인의 PG 미접수 확정은 기존 재전송 규칙으로 즉시 처리하며, 미접수 확인 뒤 추가로 기다리거나 다시 조회하던 단계를 제거했다.
- [x] 실제 PG·은행 연동·송금 실행과 증빙 기록을 구분한다.
- [x] 과거 승인 대기·실패를 새 종료 동의로 추정하지 않도록 전환 조건을 적었다.
- [x] 실패 확정(한도 소진·전송 전 실패·PG 거절) 뒤 점주·운영자의 개별 확인 재전송 범위·조건·감사 기록과 운영자 직접 재시도의 권한 거부 시나리오를 연결했다.

- [x] 자동 재전송 한도는 백그라운드 작업에만 적용하고 개별 확인의 확정 미접수 재전송에는 적용하지 않는다. 한도 소진 실패 건도 개별 조회 후 별도 버튼 없이 처리한다.

## 구현 전·후 검증

- [ ] 실제 PG의 미접수·최종 실패·멱등 키·서명 보장을 확인한다.
- [ ] 기존 데이터의 미확정 PG 건을 정리하고 마이그레이션을 검증한다.
- [ ] 인수 시나리오별 TDD·HTTP E2E와 주요 실패 구현 검출을 수행한다.
- [ ] 별도 환불금 지급의 실제 증빙 확인·담당 운영 절차를 검증한다.

## 검토 범위

문서의 요구사항·상태·연결 대조와 실제 구현·설계 완전성 보증은 구분한다. 이전 v0.2의 통과 기록은 당시 버전의 이력이며 이번 비호환 변경의 구현 검증 결과가 아니다. 소스·DB·테스트는 이 문서 수정만으로 완료되지 않는다.
