# 제품 명세: 환불 기능 완료

**갱신일**: 2026-10-26 · **상태**: 초안 · **기준**: 정책 v0.3

## 헤드라인

고객과 점주가 환불을 확정하면 이용을 종료하고 돈을 돌려주는 절차를 시작한다. 결제사 지급이 실패해도 이용권을 되살리지 않는다. 미지급액은 같은 환불 건에서 계속 관리하며, 고객은 이용 종료와 돈 반환 상태를 따로 확인한다.

## 용어

- **환불 확정**: 안내와 동의 후 이용 종료와 돌려줄 금액을 결정한 것.
- **새 식별자를 발급한 PG 취소 요청**: 실패한 요청을 대신해 새 PG 취소 요청 식별자로 보내는 PG 취소 요청. 기존 환불 건·금액과 실패 기록은 유지한다.
- **환불금 지급 처리 중**: 확정한 돈을 돌려주는 절차가 진행 중인 상태.
- **PG 취소 결과 확인 실패**: 결제사 장애 등으로 환불금 지급 결과를 확인하지 못한 상태.
- **환불금 지급 조치 필요**: 담당자가 미지급 원인이나 금액 차이를 해결해야 하는 상태.
- **환불금 지급 완료**: 합의한 돈의 지급과 필요한 검토가 끝난 상태.

## 사용자와 문제

고객은 이용하지 않을 이용권을 종료하고 합의한 환불금을 받고 싶다. 점주는 매장 기준에 맞는 금액으로 처리하고 좌석을 다시 판매하고 싶다. 고객지원 담당자는 미지급 건을 찾아 환불금 중복 지급 없이 해결해야 한다.

지금은 환불금 지급 실패 뒤 이용권을 복구하려면 이용 기간·기존 좌석·좌석 유형별 가격까지 다시 다뤄야 한다. 종료와 지급을 분리해 이 복구를 환불 절차에 넣지 않는다. 대신 환불금 지급 실패를 방치하지 않는 운영 기능이 필요하다.

## 가정

- 고객과 점주는 확정 금액과 이용 종료가 환불금 지급 실패에도 유지됨을 안내받고 동의한다.
- 기한 안의 미사용 이용권은 매장 환불도 전액이다. 기한이 지난 미사용 이용권과 사용 이력이 있는 이용권은 점주가 실결제액 범위에서 금액과 사유를 정한다.
- 결제사 결과가 불명확하면 새 지급을 시작하지 않는다.
- 별도 환불금 지급의 실제 송금은 외부에서 진행하고 담당자가 증빙을 기록한다.

## 범위

포함하는 기능은 고객 판정·점주 환불·이용 종료 동의·고정석 해제·PG 취소 요청과 조회·재전송·미지급 목록·점주의 한도 소진 건 재시도·운영자 재시도·별도 환불금 지급 예약과 증빙·실제 지급 원장·결과 통보 인증·조회 권한과 읽음이다.

실제 결제사·은행 연결, 송금 실행, 매출 기록·정산 마감·매장 송금, 참고 환불액 제안, 외부 알림, 이용권 강제 폐기, 일별 대사·PG 결과 정정·초과액 회수는 제외한다.

## 사용 사례

### 사용 사례 1: 미사용 이용권을 전액 환불하기

**조건** 고객이 기한 안의 미사용 이용권을 가진다.
**만약** 종료와 전액 환불을 안내받고 동의한다.
**그러면** 이용 종료·좌석 해제·금액을 확정하고 환불금 지급 상태를 따로 표시한다.

### 사용 사례 2: 이용 중인 이용권을 매장에서 환불하기

**조건** 점주가 자기 매장 이용권의 금액과 사유를 정한다.
**만약** 이용 종료와 필요한 퇴실 동의를 받아 실행한다.
**그러면** 퇴실·이용 종료·좌석 해제 뒤 지급을 시작하고 담당자와 금액을 기록한다.

### 사용 사례 3: 환불금 지급 실패를 확인하기

**조건** 환불은 확정됐지만 결제사 PG 취소 요청이 실패했다.
**만약** 고객이나 점주가 내역을 확인한다.
**그러면** 이용 종료는 유지되고 미지급액과 담당자 처리 상태가 보인다.

### 사용 사례 4: 미지급 금액을 재처리하기

**조건** 결제사 환불금 지급 실패가 확실하고 미확정 환불금 지급이 없다.
**만약** 고객지원 담당자가 원인을 해결해 재시도한다.
**그러면** 같은 환불 건의 합의 금액으로 지급을 다시 시도한다.

### 사용 사례 4a: 자동 재전송이 끝난 환불을 점주가 다시 시도하기

**조건** 자기 매장 환불에서 결제사가 취소 요청을 받지 못했고 자동 재전송도 한도를 소진해 실패했다. 실제로 지급된 금액과 진행 중인 다른 환불금 지급은 없다.
**만약** 점주가 그 환불의 결제사 처리 결과 확인을 실행하고 미접수가 다시 확실히 확인된다.
**그러면** 서버가 별도 버튼 없이 기존 환불 금액의 취소 요청을 새 PG 취소 요청 식별자로 PG에 보낸다. 이전 실패 이력과 이용 종료는 유지한다. 새 식별자를 발급한 PG 취소 요청에도 자동 재전송 한도를 적용하고, 또 실패하면 사람이 다시 실행해야 한다. 사람이 실행한 개별 확인의 미접수 결과로 재시도하며, 백그라운드 작업이 임의로 새 식별자를 발급한 PG 취소 요청을 만들지는 않는다.

### 사용 사례 5: 별도 환불금 지급을 기록하기

**조건** 결제사 결과가 모두 확인됐고 미지급액이 남아 있다.
**만약** 담당자가 지급을 예약하고 실제 지급 뒤 증빙을 기록한다.
**그러면** 다른 환불금 지급을 막은 채 실제 금액을 한 번만 반영하고 환불금 지급 완료 여부를 갱신한다.

### 사용 사례 6: 문의받은 환불 한 건의 최신 결과 확인하기

**조건** 점주가 자기 매장 환불을 보거나 고객지원 담당자가 환불을 확인한다.
**만약** 그 환불의 결제사 처리 결과 확인을 실행한다.
**그러면** 미확정 환불금 지급 한 건만 바로 조회해 확인 시각과 결과를 보여준다. 이미 조회 중이거나 최근 조회가 있으면 중복 호출 없이 안내한다. 결과가 불명확하면 확인 중으로 남기고, 확정 실패라면 담당자 조치가 필요함을 안내한다. 결제사가 취소 요청을 받지 않았음을 확실히 확인하면 자동 재전송 횟수와 관계없이 즉시 다시 보낸다. 한도 소진으로 실패한 환불도 개별 조회 후 재시도할 수 있으며 별도 버튼은 요구하지 않는다. 환불 금액과 이용 종료를 유지하고 다른 환불의 일괄 확인은 시작하지 않는다.

## 성공 지표

- 종료·금액이 확정되기 전에 지급을 시작한 건수는 0건이다.
- 환불금 지급 실패 후 이용권을 복구하거나 새 환불을 만드는 건수는 0건이다.
- 미지급 건 누락과 환불금 중복 지급·원장 중복은 0건이다.
- 종료된 이용권으로 입실한 건수는 0건이다.
- 결과 불명 상태에서 다른 환불금 지급을 시작한 건수는 0건이다.

## 위험과 운영 확인

고객은 이용 종료 후 돈을 받기까지 기다릴 수 있다. 확정 화면과 내역에서 이를 명확히 안내하고 환불금 지급 지연·미지급 담당을 확인할 수 있어야 한다. 별도 환불금 지급 증빙은 실제 지급을 확인한 담당자가 기록하며, 환불금 지급 여부를 모르면 다시 송금하지 않는다. 기한 연장이나 좌석 변경을 환불금 지급 실패 해결책으로 안내하지 않는다.
