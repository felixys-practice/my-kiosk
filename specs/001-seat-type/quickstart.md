# 검증 가이드: 좌석 타입(고정석·자유석) 추가

기능이 끝까지 동작하는지 확인하는 시나리오다. 요청·응답 형식은 [contracts/rest-api.md](./contracts/rest-api.md),
필드와 상태 전이는 [data-model.md](./data-model.md)를 참고한다.

## 사전 준비

```bash
docker compose up -d            # PostgreSQL 16, Redis 7
npx prisma migrate dev          # 좌석 타입 마이그레이션 적용
npm run prisma:seed             # 시드 데이터
npm run start:dev
```

마이그레이션 직후 확인: 기존 좌석·상품·이용권이 모두 `FREE`인지(FR-016, SC-001).

## 자동 검증

```bash
npm run test -- --testPathPatterns="seat|ticket-seat|order|usage-session|ticket-pause"   # 단위 테스트
npm run test:e2e -- --testPathPatterns=seat-type                                         # E2E 테스트
npx eslint .
npm run build
```

## 경우의 수 표

규칙이 여러 조건의 조합으로 정해지는 곳은 표로 경우를 모두 나열하고, 칸마다 검증하는 시나리오(QS)를 적는다.
표의 모든 칸에 QS 번호 또는 단위 테스트가 있어야 "모든 경우를 테스트했다"고 본다.

### 표 1. 입실 규칙 (FR-011)

| 이용권 | 앉으려는 좌석 | 결과 | QS |
|---|---|---|---|
| 고정석 | 내 지정 좌석 | 입실 | 11 |
| 고정석 | 다른 고정석 | 거부 (400) | 11 |
| 고정석 | 자유석 | 거부 (400) | 11a |
| 고정석 (지정 좌석 없음: 자동 취소 대기 중) | 아무 좌석 | 거부 (400) | 11b |
| 자유석 | 자유석 | 입실 | 12 |
| 자유석 | 고정석 | 거부 (400) | 12 |

### 표 2. 점주의 이용권 좌석 변경 (FR-013~015b, FR-019)

| 고정석 | 자유석 | 변경, 지정 해제 | 즉시 퇴실 후 변경 | 14a / 14 |
| 고정석 | 다른 빈 고정석 | 이동 | 이용 상태 유지한 채 이동 | 15a / 15 |
| 고정석 | 이미 지정된 고정석 | 거부 (409) | 거부 (409) | 15b |

| (모든 경우) | 사유 없음 | 거부 (400) | 거부 (400) | 16 |
