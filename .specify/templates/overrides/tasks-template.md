# Task 목록: [기능 이름]

**입력**: `/specs/[###-기능-이름]/`의 설계 문서

**선행 문서**: plan.md(필수), spec.md(필수, 사용자 스토리), research.md, data-model.md, contracts/, quickstart.md

**테스트**: 헌법 원칙 III에 따라 테스트는 필수다. 사용자 스토리마다 테스트 task를 구현 task보다 앞에 둔다.
TDD 사이클(실패 확인, 구현, refactoring, 기록, 커밋)은 tdd 확장(`/speckit-tdd-plan`, `/speckit-tdd-run`)이 진행한다.

**구성**: 사용자 스토리별로 묶어 각 스토리를 따로 구현하고 따로 검증할 수 있게 한다.

## 형식: `[ID] [P?] [Story] 설명`

- **[P]**: 동시에 진행 가능(다른 파일, 의존 없음)
- **[Story]**: 해당 사용자 스토리(US1, US2, US3 등)
- 설명에 정확한 파일 경로를 적는다
- 동작 ID(`[A1]`, `[U3]` 등)는 `/speckit-tdd-plan`이 테스트 목록(`tdd/test-list.md`)을 만들면서 task에 붙인다.
  `/speckit-tasks` 단계에서는 붙이지 않는다

## 프로젝트 규칙

- **QS 번호**: E2E 테스트 이름 끝에 quickstart.md 시나리오 번호 `(QS-n)`을 붙인다. 단위 테스트 이름에는 붙이지 않는다
- **거부 동작 (헌법 VI)**: 요청 거부를 검증하는 E2E는 상태 코드와 함께 `error.code`를 검증하고,
  단위 테스트는 해당 도메인 에러 클래스를 검증한다. 기대 코드는 contracts의 오류 코드 대응표를 따른다.
  DTO 형식 검증(`ValidationPipe`) 실패는 상태 코드만 검증한다
- **실행 명령**: `.specify/memory/tdd-profile.md`의 명령을 쓴다

## 경로 관례

- plan.md의 프로젝트 구조를 따른다. 단위 테스트는 소스 옆 `*.spec.ts`, E2E는 `test/*.e2e-spec.ts`

## 의존 관계와 실행 순서

### 단계 의존

- **준비(Phase 1)**: 의존 없음. 바로 시작할 수 있다
- **기반(Phase 2)**: 준비 완료 후. **모든 사용자 스토리를 막는다**
- **사용자 스토리(Phase 3+)**: 기반 완료 후
  - 우선순위 순서(P1 → P2 → P3)로 진행하거나, 파일이 겹치지 않으면 동시에 진행한다
- **마무리(마지막 Phase)**: 원하는 사용자 스토리가 모두 끝난 뒤

### 사용자 스토리 의존

- **사용자 스토리 1 (P1)**: 기반 완료 후 시작. 다른 스토리에 의존하지 않는다
- **사용자 스토리 2 (P2)**: 기반 완료 후 시작. 스토리 1과 연결될 수 있지만 따로 검증할 수 있어야 한다

### 사용자 스토리 안의 순서

- 테스트 task는 구현 task보다 MUST 먼저 하고, 구현 전에 실패를 확인한다(헌법 III)
- 모델 → 서비스 → 엔드포인트 순서
- 핵심 구현 → 연결
- 스토리를 끝낸 뒤 다음 우선순위로 간다

### 동시 진행 가능

- [P]가 붙은 준비·기반 task는 동시에 진행할 수 있다
- 기반이 끝나면 사용자 스토리를 동시에 시작할 수 있다
- 같은 테스트 파일을 함께 고치는 task는 충돌에 주의한다

## 구현 전략

### MVP 먼저 (사용자 스토리 1만)

1. 준비 완료
2. 기반 완료(모든 스토리를 막는다)
3. 사용자 스토리 1 완료
4. **멈추고 검증**: 사용자 스토리 1을 단독으로 검증한다

### 점진적 진행

1. 준비 + 기반 → 기반 준비 완료
2. 사용자 스토리 1 추가 → 단독 검증
3. 사용자 스토리 2 추가 → 단독 검증
4. 각 스토리는 앞 스토리를 깨뜨리지 않고 기능을 더한다

## 참고

- [P] task = 다른 파일, 의존 없음
- [Story] 표기는 task를 사용자 스토리에 연결해 추적할 수 있게 한다
- 각 사용자 스토리는 따로 완료하고 따로 검증할 수 있어야 한다
- 동작 ID가 붙은 task는 `/speckit-tdd-run`이 사이클마다 커밋하고 체크한다. 그 밖의 task는 task나 논리 묶음마다 커밋한다
- 체크포인트마다 멈추고 스토리를 단독으로 검증할 수 있다
- 피할 것: 모호한 task, 같은 파일 충돌, 스토리 독립성을 깨는 스토리 간 의존
- 커밋 메시지는 한글로 작성한다
