> **환불 확정 이용권과 일반 정지 구분(2026-10-26).** 아래 시퀀스는 기존 일반 정지·재개 설명이다. [환불 v0.3](../../specs/002-refund-completion/spec.md)은 이용을 종료하며, PG 실패 시 정지를 재개하거나 기한을 연장하지 않는다. 새 설계에서는 TicketPause.closedAt/closeReason으로 환불 종료를 기록하고, 활성 정지 조회는 resumedAt·closedAt이 모두 null인지 검사한다. 구현 예정 상세는 [데이터 모델](../../specs/002-refund-completion/data-model.md)을 따른다.

# 이용권 정지/재개 시퀀스

## 아키텍처 개요

세션 종료 로직은 `SessionLifecycleService`가 단일 원천(SSoT)으로 관리한다.
`TicketPauseService`와 `UsageSessionRepository` 모두 이 서비스에 위임하여 FOR UPDATE 락 → ENDED 전이 → 시간권 잔여시간 차감 → EXHAUSTED 자동 전이를 일관되게 처리한다.

```
UsageSessionModule ──→ SessionLifecycleModule
TicketModule ──────→ SessionLifecycleModule
UsageSessionModule ──→ TicketModule (기존)
```

---

## 1. 정지 (pauseTicket)

### 1-1. 시간권 정지 — 활성 세션 있는 경우

가장 복잡한 경로. 활성 세션 종료(SessionLifecycleService 위임) → TicketPause 생성 → BullMQ Job 제거.

```mermaid
sequenceDiagram
    participant C as Client
    participant Ctrl as TicketPauseController
    participant Svc as TicketPauseService
    participant Repo as TicketPauseRepository
    participant SL as SessionLifecycleService
    participant DB as PostgreSQL
    participant Q as BullMQ

    C->>Ctrl: PATCH /tickets/:ticketId/pause
    Ctrl->>Svc: pauseTicket(ticketId, userId, reason?)

    rect rgb(240, 248, 255)
        Note over Svc,DB: 트랜잭션 시작

        Svc->>Repo: getTicketForUpdate(ticketId, tx)
        Repo->>DB: SELECT ... FROM tickets<br/>WHERE id = ? FOR UPDATE
        DB-->>Repo: ticket { type: TIME, status: ACTIVE, remainingMinutes: 120 }
        Repo-->>Svc: ticket

        Note right of Svc: 검증: status === ACTIVE ✅

        Svc->>Repo: findActivePause(ticketId, tx)
        Repo->>DB: SELECT ... FROM ticket_pauses<br/>WHERE ticket_id = ? AND resumed_at IS NULL
        DB-->>Repo: null (정지 중 아님)
        Repo-->>Svc: null ✅

        Svc->>Repo: findActiveSessionId(ticketId, tx)
        Repo->>DB: SELECT id FROM usage_sessions<br/>WHERE ticket_id = ? AND ended_at IS NULL
        DB-->>Repo: sessionId
        Repo-->>Svc: sessionId

        Note right of Svc: 활성 세션 존재 → SessionLifecycleService에 종료 위임

        Svc->>SL: endSession(sessionId, now, tx)
        SL->>DB: SELECT us.*, t.type FROM usage_sessions us<br/>JOIN tickets t ON ... WHERE us.id = ?<br/>FOR UPDATE OF us
        DB-->>SL: session { status: ACTIVE, ticketType: TIME, startedAt }

        SL->>DB: UPDATE usage_sessions SET status = 'ENDED', ended_at = now
        Note right of SL: 시간권 → 소비 시간 차감
        SL->>DB: UPDATE tickets<br/>SET remaining_minutes = GREATEST(0, remaining_minutes - consumed),<br/>status = CASE WHEN ≤ 0 THEN 'EXHAUSTED' ELSE status END
        SL-->>Svc: { ticketId, bullmqJobId, alreadyEnded: false }

        Svc->>Repo: createPause({ ticketId, pausedAt, pausedBy, reason }, tx)
        Repo->>DB: INSERT INTO ticket_pauses
        Note over DB: partial unique index<br/>(ticket_id) WHERE resumed_at IS NULL<br/>→ 동시 삽입 1건만 허용
        Repo-->>Svc: ticketPause

    Note over Svc,DB: 트랜잭션 커밋
    end

    Svc->>Q: queue.remove(bullmqJobId)
    Note right of Q: 자동만료 Job 제거<br/>실패해도 endSession 멱등 처리로 안전

    Svc-->>Ctrl: void
    Ctrl-->>C: 200 OK
```

### 1-2. 정기권 정지 — 활성 세션 있는 경우

SessionLifecycleService가 ticketType을 내부적으로 판별하므로 서비스 호출 방식은 시간권과 동일하다. 차이는 DB 내부에서 remaining_minutes 차감이 발생하지 않는다는 점.

```mermaid
sequenceDiagram
    participant Svc as TicketPauseService
    participant Repo as TicketPauseRepository
    participant SL as SessionLifecycleService
    participant DB as PostgreSQL

    rect rgb(240, 248, 255)
        Note over Svc,DB: 트랜잭션

        Svc->>Repo: getTicketForUpdate(ticketId, tx)
        DB-->>Svc: ticket { type: PERIOD, status: ACTIVE }

        Svc->>Repo: findActivePause → null ✅
        Svc->>Repo: findActiveSessionId → sessionId

        Note right of Svc: SessionLifecycleService에 종료 위임 (TIME/PERIOD 분기 없음)

        Svc->>SL: endSession(sessionId, now, tx)
        SL->>DB: SELECT ... JOIN tickets ... FOR UPDATE OF us
        SL->>DB: UPDATE usage_sessions SET status = 'ENDED', ended_at = now
        Note right of DB: 정기권 → remaining_minutes 차감 없음
        SL-->>Svc: { ticketId, bullmqJobId, alreadyEnded: false }

        Svc->>Repo: createPause(...)
        Repo->>DB: INSERT INTO ticket_pauses
    end
```

### 1-3. 정지 — 활성 세션 없는 경우

세션 종료 단계를 건너뛴다. BullMQ Job 제거도 불필요.

```mermaid
sequenceDiagram
    participant Svc as TicketPauseService
    participant Repo as TicketPauseRepository
    participant DB as PostgreSQL

    rect rgb(240, 248, 255)
        Note over Svc,DB: 트랜잭션

        Svc->>Repo: getTicketForUpdate(ticketId, tx)
        DB-->>Svc: ticket { status: ACTIVE }

        Svc->>Repo: findActivePause → null ✅
        Svc->>Repo: findActiveSessionId → null (세션 없음)

        Note right of Svc: 활성 세션 없음 → SessionLifecycleService 호출 생략

        Svc->>Repo: createPause(...)
        Repo->>DB: INSERT INTO ticket_pauses
    end
```

### 1-4. 정지 실패 케이스

```mermaid
sequenceDiagram
    participant C as Client
    participant Svc as TicketPauseService
    participant Repo as TicketPauseRepository
    participant DB as PostgreSQL

    Note over C,DB: Case A: ACTIVE가 아닌 티켓
    C->>Svc: pauseTicket(ticketId, ...)
    Svc->>Repo: getTicketForUpdate(ticketId, tx)
    DB-->>Svc: ticket { status: UNUSED }
    Svc--xC: 400 DomainBadRequestError<br/>"정지할 수 없는 상태의 티켓입니다 (현재: UNUSED)"

    Note over C,DB: Case B: 이미 정지 중
    C->>Svc: pauseTicket(ticketId, ...)
    Svc->>Repo: getTicketForUpdate → ACTIVE ✅
    Svc->>Repo: findActivePause(ticketId, tx)
    DB-->>Svc: activePause (resumed_at IS NULL)
    Svc--xC: 409 DomainConflictError<br/>"이미 정지 중인 티켓입니다"

    Note over C,DB: Case C: 동시 정지 요청 (Race)
    C->>Svc: pauseTicket(ticketId, ...) × 2 동시
    Note right of DB: 요청 A: FOR UPDATE 락 획득 → 정지 생성 성공<br/>요청 B: 락 대기 → 획득 후 findActivePause → 이미 존재 → 409
```

## 2. 재개 (resumeTicket)

### 2-1. 시간권 재개

정지 기간만큼 `minuteExpireDeadline`을 연장한다.

```mermaid
sequenceDiagram
    participant C as Client
    participant Ctrl as TicketPauseController
    participant Svc as TicketPauseService
    participant Repo as TicketPauseRepository
    participant DB as PostgreSQL

    C->>Ctrl: PATCH /tickets/:ticketId/resume
    Ctrl->>Svc: resumeTicket(ticketId, userId, reason?)

    rect rgb(255, 248, 240)
        Note over Svc,DB: 트랜잭션 시작

        Svc->>Repo: getTicketForUpdate(ticketId, tx)
        Repo->>DB: SELECT ... FOR UPDATE
        DB-->>Repo: ticket { type: TIME, status: ACTIVE,<br/>minuteExpireDeadline: 2026-09-10 }
        Repo-->>Svc: ticket

        Svc->>Repo: findActivePause(ticketId, tx)
        Repo->>DB: SELECT ... WHERE resumed_at IS NULL
        DB-->>Repo: activePause { id, pausedAt: 09-07 14:00 }
        Repo-->>Svc: activePause ✅

        Note right of Svc: 검증: status === ACTIVE ✅

        Svc->>Repo: resumePause(pauseId, { resumedAt: now, resumedBy, reason }, tx)
        Repo->>DB: UPDATE ticket_pauses<br/>SET resumed_at = now, resumed_by = ?, resumed_reason = ?
        Repo-->>Svc: updatedPause

        Note right of Svc: pauseDuration = now(09-08 10:00) - pausedAt(09-07 14:00) = 20시간<br/>newDeadline = minuteExpireDeadline + 20시간

        Svc->>Repo: extendTicketDeadline(ticketId, { minuteExpireDeadline: newDeadline }, tx)
        Repo->>DB: UPDATE tickets SET minute_expire_deadline = ?
        Repo-->>Svc: void

    Note over Svc,DB: 트랜잭션 커밋
    end

    Svc-->>Ctrl: void
    Ctrl-->>C: 200 OK
    Note right of C: 재개 ≠ 재입실<br/>새 세션을 만들지 않는다
```

### 2-2. 정기권 재개

정지 기간만큼 `expiresAt`을 연장한다.

```mermaid
sequenceDiagram
    participant Svc as TicketPauseService
    participant Repo as TicketPauseRepository
    participant DB as PostgreSQL

    rect rgb(255, 248, 240)
        Note over Svc,DB: 트랜잭션

        Svc->>Repo: getTicketForUpdate(ticketId, tx)
        DB-->>Svc: ticket { type: PERIOD, status: ACTIVE,<br/>expiresAt: 2026-10-07 }

        Svc->>Repo: findActivePause → activePause { pausedAt: 09-07 }
        Note right of Svc: 검증: status === ACTIVE ✅

        Svc->>Repo: resumePause(pauseId, { resumedAt: now, ... }, tx)
        Repo->>DB: UPDATE ticket_pauses SET resumed_at = now

        Note right of Svc: pauseDuration = now(09-10) - pausedAt(09-07) = 3일<br/>newExpiresAt = expiresAt(10-07) + 3일 = 10-10

        Svc->>Repo: extendTicketDeadline(ticketId, { expiresAt: 2026-10-10 }, tx)
        Repo->>DB: UPDATE tickets SET expires_at = ?
    end
```

### 2-3. 재개 실패 케이스

```mermaid
sequenceDiagram
    participant C as Client
    participant Svc as TicketPauseService
    participant DB as PostgreSQL

    Note over C,DB: Case A: 정지 중이 아닌 티켓
    C->>Svc: resumeTicket(ticketId, ...)
    Svc->>DB: findActivePause → null
    Svc--xC: 400 DomainBadRequestError<br/>"정지 상태가 아닌 티켓입니다"

    Note over C,DB: Case B: 정지 중 관리자가 REVOKED 처리
    C->>Svc: resumeTicket(ticketId, ...)
    Svc->>DB: getTicketForUpdate → { status: REVOKED }
    Svc->>DB: findActivePause → activePause ✅
    Note right of Svc: status ≠ ACTIVE
    Svc--xC: 400 DomainBadRequestError<br/>"재개할 수 없는 상태의 티켓입니다 (현재: REVOKED)"
```

## 3. 동시성 방어 구조

```mermaid
sequenceDiagram
    participant A as 요청 A
    participant B as 요청 B
    participant DB as PostgreSQL

    Note over A,DB: 같은 티켓에 대한 동시 정지 요청

    A->>DB: SELECT ... FOR UPDATE (ticket)
    Note right of DB: A가 행 수준 락 획득

    B->>DB: SELECT ... FOR UPDATE (ticket)
    Note right of DB: B는 락 대기 (블로킹)

    A->>DB: findActivePause → null ✅
    A->>DB: INSERT INTO ticket_pauses
    Note right of DB: partial unique index 통과 ✅
    A->>DB: COMMIT
    Note right of DB: A 트랜잭션 완료, 락 해제

    Note right of DB: B 락 획득
    B->>DB: findActivePause → activePause 존재
    B--xB: 409 DomainConflictError

    Note over A,DB: 3중 방어
    Note right of DB: 1. FOR UPDATE 락 → 직렬화<br/>2. Partial Unique Index → DB 수준 보장<br/>3. findActivePause() → 의미 있는 에러 메시지
```

## 4. 세션 종료 위임 구조 (SessionLifecycleService)

세션 종료가 필요한 두 모듈이 동일한 서비스에 위임하는 구조.

```mermaid
sequenceDiagram
    participant URS as UsageSessionRepository
    participant TPS as TicketPauseService
    participant SL as SessionLifecycleService
    participant DB as PostgreSQL

    Note over URS,DB: 경로 A: 세션 자동만료 (BullMQ Job 트리거)
    URS->>SL: endSession(sessionId, now, tx)
    SL->>DB: SELECT ... JOIN tickets FOR UPDATE OF us
    SL->>DB: UPDATE usage_sessions SET status = 'ENDED'
    SL->>DB: UPDATE tickets SET remaining_minutes = ... (TIME만)
    SL-->>URS: EndSessionResult

    Note over TPS,DB: 경로 B: 이용권 정지 시 활성 세션 강제 종료
    TPS->>SL: endSession(sessionId, now, tx)
    SL->>DB: SELECT ... JOIN tickets FOR UPDATE OF us
    SL->>DB: UPDATE usage_sessions SET status = 'ENDED'
    SL->>DB: UPDATE tickets SET remaining_minutes = ... (TIME만)
    SL-->>TPS: EndSessionResult

    Note over URS,DB: 두 경로 모두 동일한 로직 실행<br/>FOR UPDATE → ENDED → 시간권 차감 → EXHAUSTED 전이<br/>이미 종료된 세션은 멱등 처리 (alreadyEnded: true)
```
