### 1. 용어 사전

| 용어 | 정의 |
|---|---|
| 이용권 | 고객이 산 시간권 또는 정기권 1개. 주문 상품 1개와 1:1로 대응하며, 환불은 이용권 1개 단위로 한다 |
| 시간권 | 구매한 시간(분)만큼 이용하는 이용권 |
| 정기권 | 처음 이용(활성화)한 날부터 구매한 일수 동안 이용하는 이용권 |
| 미사용 | 이용권을 한 번도 쓰지 않은 상태. 판정 기준은 2-2. 고객이 직접 환불할 수 있는 유일한 상태다 |
| 사용 이력 있음 | 미사용이 아닌 모든 상태. 지금 이용 중인 경우를 포함한다 |
| 실결제액 | 이용권별로 실제 결제된 금액(상품 가격 − 상품 할인). 환불 금액의 기준이다. 설계 문서의 "원가"는 이 금액을 뜻한다 |
| 환불 신청 시각 | 고객이 환불을 신청한 시각. 이 문서의 판정 기준 시각이다 |
| 매장 환불 | 사용 이력이 있는 이용권을, 고객의 요청을 받은 매장 점주가 직접 환불하는 것(§5) |
| 처리 중 | 결제 취소를 요청했지만 PG 결과가 아직 확정되지 않은 상태. 이용권 상태는 바뀌지 않는다. 요청이 PG에 도달하지 않은 것으로 확인되면 실패로 끝나고 다시 신청할 수 있다 |
| 환불 완료 | PG가 결제 취소를 확정한 때. 이때 이용권 소멸과 정산의 환불 기록이 함께 일어난다 |

### 2. 정책 본문

#### 2-1. 환불 판정 (판정형)

##### 평가 순서

1. **대상 여부(T) 규칙**을 `우선순위` 순으로 확인한다. 하나라도 어기면 즉시 거절하고 평가를 중단한다.
2. **가능 조건(C) 규칙**은 전부 평가하고, 어긴 규칙을 모두 기록한다.
3. **대표 사유**는 어긴 규칙 중 `우선순위` 숫자가 가장 작은 규칙으로 한다.
4. **판정 결과**는 결정 테이블의 결과 코드로 정하고, 결과별로 일어나는 일은 아래 **판정 결과** 표를 따른다.

##### 결정 테이블

| 우선순위 | 규칙 ID | 구분 | 조건 | 판정 기준 | 결과 코드 | 거절 사유 코드 | 파라미터 | 예외 승인 |
|---|---|---|---|---|---|---|---|---|
| 10 | REF-T01 | 대상 여부 | 본인 이용권이 아님 | 신청한 고객과 이용권 소유자가 다름 | `REJECTED` | `NOT_TICKET_OWNER` | - | 불가 |
| 20 | REF-T02 | 대상 여부 | 결제가 성공 상태가 아님 | 이용권 주문의 결제 상태가 결제 대기(`PENDING`)·요청 중(`REQUESTED`)·실패(`FAILED`)·취소(`CANCELLED`) 중 하나 | `REJECTED` | `PAYMENT_NOT_COMPLETED` | - | 불가 |
| 30 | REF-T03 | 대상 여부 | 이미 환불됨 | 같은 이용권에 환불 완료 기록이 있음 | `REJECTED` | `ALREADY_REFUNDED` | - | 불가 |
| 40 | REF-T04 | 대상 여부 | 환불 없이 이미 소멸됨 | 이용권이 소멸(`REVOKED`) 상태이고 환불 완료 기록은 없음(관리자 강제 소멸) | `REJECTED` | `TICKET_REVOKED` | - | 불가 |
| 50 | REF-T05 | 대상 여부 | 처리 중인 환불이 있음 | 같은 이용권에 처리 중인 환불이 있음 | `REJECTED` | `REFUND_IN_PROGRESS` | - | 불가 |
| 10 | REF-C01 | 가능 조건 | 사용 이력이 있음 | 미사용 판정(2-2)에서 "사용 이력 있음" | `REJECTED` | `USED_TICKET` | - | 가능(§5) |
| - | - | - | 어긴 규칙 없음 | - | `AUTO_REFUND` | - | - | - |

- 판정 시점: 환불 신청 시각.
- 이용 기한이 지난 미사용 이용권을 어떻게 판정할지는 `[결정 필요 D-01]`. 지금은 기한을 보지 않으므로 자동 환불된다.
- REF-T03을 REF-T04보다 앞에 둔다. 환불이 완료된 이용권도 소멸 상태이므로, 순서가 반대면 "이미 환불됨" 대신 "소멸됨"으로 안내된다.

##### 판정 결과

| 결과 코드 | 판정 결과 | 일어나는 일 | 시점 |
|---|---|---|---|
| `REJECTED` | 거절 | 이용권·결제에 변화 없음. 대표 사유의 안내 문구(§4)를 보여준다. 대표 사유가 REF-C01이면 매장에 환불을 요청하라고 안내한다(§5) | 신청 즉시 |
| `AUTO_REFUND` | 자동 환불 | 실결제액 전액(§2-3)의 결제 취소를 요청한다. 환불 완료되면 이용권이 소멸하고 정산에 환불이 기록된다 | 취소 요청: 신청 즉시 / 소멸·정산: 환불 완료 시 |

#### 2-2. 미사용 판정

위에서부터 확인해 처음 맞는 행으로 판정한다.

| 순서 | 상품·상태 | 판정 |
|---|---|---|
| 1 | 지금 이용 중(좌석 사용 중) | 사용 이력 있음. 시간권은 이용이 끝날 때 남은 시간이 줄어들므로, 이용 중에는 남은 시간만으로 판단하지 않는다 |
| 2 | 정기권, 아직 처음 이용(활성화) 전 | 미사용 |
| 3 | 시간권, 남은 시간 = 구매한 시간 | 미사용 |
| 4 | 그 밖의 모든 경우 | 사용 이력 있음 |

#### 2-3. 환불 금액 (계산형)

| 항목 | 정책 |
|---|---|
| 기준 금액 | 실결제액 |
| 계산식 | `AUTO_REFUND`(미사용) → 기준 금액 전액<br>`STORE_REFUND`(매장 환불) → 매장 점주가 입력한 금액 |
| 상한 / 하한 | 상한은 기준 금액(초과 입력은 거부), 하한 없음(0원 가능) |
| 횟수 | 이용권 1개당 환불 1회. 일부만 환불하고 이용권을 계속 쓰는 경우는 없다 |
| 반올림·절사 | 해당 없음. 전액이거나 점주가 입력한 금액이라 나누는 계산이 없다 |

### 3. 파라미터 (기준값)

현재 판정에 쓰는 기준값은 없다.

### 4. 거절 사유 코드

| 거절 사유 코드 | 규칙 ID | 고객 안내 문구 |
|---|---|---|
| `NOT_TICKET_OWNER` | REF-T01 | 본인이 구매한 이용권만 환불할 수 있습니다. |
| `PAYMENT_NOT_COMPLETED` | REF-T02 | 결제가 완료되지 않은 주문입니다. |
| `ALREADY_REFUNDED` | REF-T03 | 이미 환불된 이용권입니다. |
| `TICKET_REVOKED` | REF-T04 | 사용할 수 없게 처리된 이용권입니다. 매장에 문의해 주세요. |
| `REFUND_IN_PROGRESS` | REF-T05 | 처리 중인 환불이 있습니다. 잠시 후 다시 확인해 주세요. |
| `USED_TICKET` | REF-C01 | 이용한 이용권은 매장에 환불을 요청해 주세요. |

### 5. 예외 승인

판정(§2-1)이 거절로 끝나고 고객에게 안내(§4)된 뒤에, **고객이 매장에 환불을 요청**하면 시작하는 별도 절차다. 위반한 규칙이 모두 결정 테이블에서 예외 승인 `가능(§5)`이면, 매장 점주가 이 건에 한해 직접 환불한다. 판정 기록은 바꾸지 않고 승인 기록을 따로 남긴다.

| 규칙 ID | 허용 사유 | 권한자 | 승인 시 필수 기록 |
|---|---|---|---|
| REF-C01 | 매장 점주가 매장 운영 기준에 따라 판단한다(사용 기간, 남은 이용량, 고객 사정 등) | 매장 점주 | 점주, 승인 시각, 승인 사유, 환불 금액 |

##### 예외 승인 결과

| 결과 코드 | 판정 결과 | 일어나는 일 | 시점 |
|---|---|---|---|
| `STORE_REFUND` | 매장 환불 | 점주가 입력한 금액(§2-3)의 결제 취소를 요청한다. 환불 완료되면 이용권이 소멸하고 정산에 환불이 기록된다. 이용 중인 이용권이면 `[결정 필요 D-02]` | 취소 요청: 점주 실행 즉시 / 소멸·정산: 환불 완료 시 |

- 사용 이력 건의 환불 금액은 매장마다 공제 기준(사용 기간, 수수료 등)이 달라 시스템이 계산하지 않고 점주가 정한다.
